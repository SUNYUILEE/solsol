# 실제 연구 실행의 화면 품질 보완 기준

적용 작업: TASK-20260909T021656Z-4630A20A. CHANGE_INTEGRATION. 기존 Quality 2.0.1을 낮추거나 과거 PASS를 상속하지 않는다. 사용자 거절은 실제 과업 실패이며 구조 감사 PASS로 해소되지 않는다.

1. 저장 실행을 열기→해 선택→지도 비교→세대 이동→필터→큰 지도→새 계산의 실제 경로를 검사한다. 작은 fixture와 정적 DOM만으로 통과시키지 않는다. 이번 회귀 기준은 실제 EOIR 150후보·409누적해·501체크포인트·46092NFE 실행이다.
2. 서버 시간, JSON 처리, Hamming 계산, 브라우저 선택 반응, 세대 요청 횟수와 최대 동시 요청을 따로 기록한다. 150ms 이상 응답의 즉시 상태 피드백은 기존 제품 표준을 따른다. 알려진 수십 초 UI 정지를 반복하는 경로는 차단 결함이다.
3. 최종 슬라이더 의도가 표시되어야 한다. 늦은 응답이 다른 계약·실행·세대를 덮으면 실패다. 캐시 키와 수명은 계약·실행·불변 체크포인트에 결속하고 계산 중 최신 결과를 영구 캐시하지 않는다.
4. 해가 있으면 명시적으로 선택한 배치가 보여야 한다. 처음 표시한 비용순 중간 배치는 추천이나 최적 배치가 아니다. 목표 미달·빈 결과·같은 목적값의 다른 구조를 구분하며 필터 결과가 없으면 이전 해를 남기지 않는다.
5. 초기/진화 및 고정 기준/선택 해를 같은 축척에서 비교한다. 기준 행·세대와 선택 행·세대, 추가/제거 표시, 비용·센서 수를 확인한다. 기본·큰 지도에 같은 해석을 제공한다. 축척 맞춤은 가용 영역에 지도 전체를 보여야 한다.
6. 1920×1080,1440×900,1280×720 실제 Chromium 화면을 검토한다. 작은 화면에서 설정·분석이 지도를 밀어 없애면 실패다. 이번 지도 수정은 최소 200px 비교 캔버스를 진단 조건으로 삼고, 지도 우선·분석 펼치기를 함께 검사한다. 이 수치는 과학 정확도 기준이 아니라 화면 회귀 조건이다.
7. RF와 EOIR, 저장 실행 없는 미리보기, 완료 이후 계산 버튼, 원시 결과 보존을 회귀검사한다. 새 계산은 기존 프로그램 경로에서 수행한다. 원시 수치·연구 시간 실패·효율 미통과 판정을 화면 수정으로 바꾸지 않는다.
8. R04 실행 증거와 R06 독립 검토를 분리한다. 사용자 평가를 대체했다고 주장하지 않으며, 모든 제품 게이트와 접근성 전체를 실행하지 않았다면 PRODUCT_EXIT PASS는 금지한다.

설계 참고 및 채택 이유: ../08_검증/R06_UI_REPAIR_REFERENCE_ACCEPTANCE_20260909.md. 실제 기능이 보이고 반응하는지를 판정하며, 참조 제품의 외관이나 마케팅 표현을 PASS 근거로 사용하지 않는다.
