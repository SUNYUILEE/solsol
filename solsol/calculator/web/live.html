시간·비용 비교의 범위

비교 기준은 현재 열어 둔 실행입니다. 다음 계산 입력을 바꿔도 기준 실행은 바뀌지 않습니다. 현재 실행을 맨 위에 고정하고 검색된 페이지의 실행을 함께 비교합니다. 전체 건수는 이 프로그램이 읽는 다섯 저장 위치의 실행과 현재 세션을 합친 수입니다. 읽기 불가 기록도 건수와 별도 행에 포함합니다. 수정시각이 같으면 실행 ID 순서이며, 현재 실행이 검색 결과 밖이어도 비교 기준으로 남습니다.

‘초기화 제외 입력 같음’은 지도·평가영역·센서 반경·자원 조건·설계·H·요청 세대·난수 시드가 같다는 뜻입니다. 자원 제한을 끈 경우 보유량 입력은 비교하지 않습니다. 실제 계산한 세대·진화 평가횟수와 초기 준비 비용은 별도로 읽으세요. 중지된 실행의 마지막 저장 세대를 요청한 마지막 세대로 해석하면 안 됩니다.

준비 시간은 LP/MILP·Greedy 및 초기 집단 준비에 사용된 시간입니다. 진화 시간은 0세대 평가·자식 생성·목적값 평가·NSGA-III 생존선택·세대 기록을 포함합니다. ‘평가 1천회당’은 이 진화 시간÷실제 진화 평가횟수×1,000인 관측 환산값이며 순수 평가기 속도나 동일 계산량을 보장하지 않습니다. 준비 평가횟수는 솔버 내부 반복·Greedy 후보 점수 검사를 포함하지 않습니다.

준비와 진화 시간의 합에도 지도 구성·저장 검산·최종 파일 쓰기·통신·화면 표시가 모두 포함되지는 않습니다. 전체 체감시간이나 프로그램 간 속도 향상률로 사용하지 마세요. 입력과 평가횟수가 같아도 코드·CPU 환경·초기 배치·솔버 종료 상태는 다를 수 있습니다. 엄밀한 비교에는 다운로드한 실행 근거와 반복 측정이 필요합니다.

비용은 각 집단에서 탐지95%·식별90%와 자원 조건을 만족하는 배치 중 가장 작은 합성 비용점수입니다. 비용 감소가 모든 모델 성능의 향상을 의미하지 않으며, 같은 비용의 배치도 여러 개일 수 있습니다. 각 실행의 배치 지도를 열어 성능과 설치 위치를 함께 확인하세요. 계산 중인 실행은 마지막으로 저장한 세대까지의 중간값입니다.

초기화 방법과 수학적 비용 경계

각 후보지의 Radar와 EO/IR 설치 여부를 0 또는 1로 놓습니다. Radar가 덮는 평가점 비율이 εD 이상이고, Radar와 EO/IR가 함께 덮는 평가점 비율이 εI 이상이라는 조건 아래 6×Radar 수 + 2×EO/IR 수를 최소화합니다. ε=(95%,90%), (100%,90%), (100%,100%)을 차례로 사용합니다. 100개 후보의 모든 조합을 나열하지 않고 제한시간 정수계획으로 배치를 구합니다. 각 MILP는 최대 5초, 전체 초기화는 목표 30초 한도입니다. 솔버 호출 종료 시 작은 시간 초과가 있을 수 있습니다.

무작위 초기화는 초기 개체를 전부 난수로 만듭니다. Greedy는 아직 덮지 못한 점을 많이 덮는 후보를 차례로 추가한 뒤 목표가 유지되는 센서를 삭제해 배치를 준비합니다. Greedy 비용은 상한이지 수학적 하한이 아닙니다. MILP는 제한시간 안에 찾은 정수 배치만 넣습니다. 정수 배치를 못 찾았다면 그 칸은 무작위로 남기며 Greedy 결과를 MILP 결과라고 대신 넣지 않습니다.

배치 후보를 중복 제거하고 목표를 통과하는 작은 변형을 더해 전체 개체의 최대 25%를 준비 배치로 채웁니다. 나머지 최소 75%는 같은 난수로 만든 무작위 배치입니다. 이후 모든 배치는 같은 NSGA-III 생존선택을 거칩니다. 준비한 배치가 0세대부터 좋다고 해서 NSGA-III가 스스로 발견했다고 해석하면 안 됩니다. 0세대와 후속 세대의 비용·배치·원시 계보를 나누어 봅니다.

LP는 설치 여부를 0~1 사이로 풀어 얻는 완화 문제입니다. 그 최적 비용과 MILP가 보고한 유효한 dual bound 중 강한 값을 하한으로 표시합니다. LP의 소수 설치를 반올림해 초기해로 넣지 않습니다. 상한과 하한이 일치하면 해당 ε의 최소비용은 인증할 수 있지만, 이것만으로 전체 파레토 프런트를 모두 알거나 그 배치가 탐지·식별까지 파레토 최적이라고 주장하지 않습니다.

초기화 방법을 같게 선택하면 설계 A/B/C의 난수 초기 부분은 같은 반복번호·개체 수에서 같습니다. MILP는 제한시간 종료 시 머신 부하에 따라 다른 정수 배치를 찾을 수 있으므로, 엄밀한 반복 비교에는 저장된 초기 배치와 솔버 근거를 사용해야 합니다. 초기화 준비 시간·평가량은 진화 평가 예산과 별도로 공개합니다. H·세대가 같아도 MILP 준비 비용을 포함한 총 노력은 같지 않습니다.

설치비용과 성능 기준 제약

설치 수를 각각 nR, nE라 하면 합성 비용은 C=6nR+2nE입니다. 단가가 모두 양수이므로 C=0이 되는 배치는 Radar 0대·EO/IR 0대뿐입니다. 이 배치는 200개 설치 스위치가 모두 0인 정상적인 표현이며 평가할 수 있습니다. 평가 결과는 탐지 0%, 식별 0%, 비용 0점입니다. 비용 목적값도 정확히 0이고, 세 목적값은 (1, 1, 0)입니다.

비용 최소화에는 성능 기준 제약이 함께 적용됩니다. 탐지 95% 이상과 식별 90% 이상이라는 두 제약을 동시에 적용합니다. 빈 배치는 탐지 95%p·식별 90%p가 부족하므로 기준 미달입니다. 기준 충족 해가 있다면 NSGA-III의 제약 우선 생존선택에서 빈 배치보다 우선됩니다. 그래서 ‘기준을 충족한 해 중 최저비용’과 ‘제약을 무시한 최저비용 0점’은 서로 다른 질문입니다.

이 표는 비용식의 계산 예시입니다. 초기화는 빈 배치를 반드시 넣지 않고, 기준 충족 Greedy/MILP 초기 배치는 빈 배치가 아닙니다. 무작위 연산에서 생성되지 않았거나 생성 후 생존하지 못한 해는 현재 세대 목록에 없습니다. 만약 실제 생존 집단에 빈 배치가 있다면 ‘생존 배치 전체 보기’로 직접 선택할 수 있습니다.

탐지·식별 제약을 없앤 별도 3목적 문제라면 빈 배치는 비용 극단의 비지배 해가 될 수 있습니다. 이는 현재 95%/90% 제약 문제의 기준 충족 해라는 뜻은 아닙니다. 비용식이 정확하다는 사실과 NSGA-III가 전역 최소비용을 찾았다는 주장은 별개입니다.

유전자 표현·교차·변이·생존선택

후보지마다 [Radar, EO/IR] 두 설치 스위치가 있습니다. [0,0]=없음, [1,0]=Radar, [0,1]=EO/IR, [1,1]=둘 다 설치입니다. A는 100곳 × 2개 = 200비트를 따로 교차합니다. B와 C는 같은 정보인 100개 후보지 상태(0,1,2,3)를 묶어서 교차합니다. 표현만 바뀌어도 가능한 물리적 배치가 늘어나는 것은 아닙니다.

A에서는 부모 [1,0]과 [0,1]을 교차하여 [1,1] 또는 [0,0]인 자식도 나올 수 있습니다. B/C의 교차 단계에서는 한 후보지의 두 스위치를 같은 부모에게서 받습니다. 이후 A/B는 평균 1.5회 무작위 비트를 뒤집습니다. C는 50% 삭제, 30% 같은 센서의 다른 후보지 이동, 20% 추가 중 한 가지를 무작위로 시도합니다. 선택한 동작이 불가능하면 그대로 둡니다. 이 연산은 현재 배치와 입력 조건을 사용하며 정답 배치를 입력받지 않습니다.

같은 지도·반경·자원 모드·보유량·무작위 초기화·반복번호·개체 수에서는 같은 초기 배치로 시작합니다. 초기화 방법을 바꾸면 주입된 배치는 달라지며 준비 근거를 별도로 확인해야 합니다. 부모 선택은 두 후보의 목표 부족분 합을 먼저 비교하고, 통과한 후보끼리는 비지배 순위가 낮은 쪽을 선택하며, 동률은 난수로 정합니다. 부모선택에는 이 규칙을 적용하고 생존선택은 pymoo의 NSGA-III 참조방향 선택을 사용합니다. 부모 둘 선택 → 교차 → 변이 → 모드에 맞는 공통 수선 → 세 목적과 목표·자원 부족분 평가 → 부모와 자식을 합쳐 NSGA-III로 다음 세대 선택을 반복합니다. 제한 끔·일부 사용에서는 커버 기여가 0인 설치를 제거합니다. 일부 사용은 초과 대수도 무작위로 줄입니다. 전부 사용은 입력 대수를 정확히 맞추도록 부족 대수를 채우며, 필요하면 기여 0인 위치도 유지합니다. 이 수선은 모든 설계에 공통이고 목적함수 평가에 앞서 적용됩니다.

참조방향·개체 수·세대 수

참조방향은 정답 배치가 아닙니다. 탐지 손실·식별 손실·비용을 축으로 하는 목적값 공간에 여러 절충 방향을 놓는 것입니다. 지도상의 후보지나 이상적인 센서 설치 좌표를 알려주는 기능이 아닙니다.

3목적에서 H는 참조 단체의 분할 수이고 방향 수는 (H+1)(H+2)/2입니다. H=7/12/19에서 36/91/210방향이며 개체 수는 36/92/212로 맞췄습니다. 이 세 값은 계산 규모별 프리셋이지 모든 문제에 대한 보편적인 최적 권장값은 아닙니다. 실제 평가 횟수는 개체 수 × (진화 업데이트 횟수 + 1)입니다. 같은 세대라도 H가 다르면 계산량이 달라집니다.

평균 1.5회 비트 변이는 수선 전 시도 횟수입니다. 자원 수선으로 초과 장비를 빼거나 전부 사용의 부족 장비를 채우면 최종 비트 변화 수는 더 많거나 적을 수 있습니다. 실제 추가 편집은 실행 계보에 별도로 기록합니다. 자원 모드가 다른 실행을 동일 연산 조건으로 비교하지 않습니다.

진화 단계는 최대 300초이며 초기화 준비와 저장 검산 시간은 별도입니다. 시간 제한 또는 중지는 완료된 마지막 세대까지 저장합니다. 검색 평가 외에 저장 시 원시 결과 재계산과 좌표 검산을 수행하며, 이 검산은 탐색이나 선택에 사용하지 않습니다.

계산 모델과 적용 범위

500m 간격의 성능 평가점에서 센서 반경 포함 여부를 계산한 합성 실험입니다. 지형·건물 차폐·고도·날씨·센서 오경보는 모델에 없습니다. 탐지 95%·식별 90%는 공간 표본 커버 기준이며 실제 드론 시험의 검출확률이 아닙니다. 후보지는 기존 20km 합성 지도에서 고정한 불규칙 100곳입니다. 30·40km 지도에서는 같은 후보 ID의 좌표를 지도 크기에 비례해 확대하므로 후보 밀도가 낮아집니다. 독립적으로 새 무작위 지도를 생성한 것은 아닙니다.

모양·면적·지도 크기·반경이 달라지면 다른 최적화 문제가 됩니다. 이전 지도의 참조해를 이 지도의 정답으로 재사용하지 않습니다. 이 동적 실험의 정확 파레토 전선은 알려져 있지 않습니다. 따라서 여기는 실제 NSGA-III가 성능 기준에 접근하면서 설치와 비용을 바꾸는지를 확인하는 화면이며, 알려진 전선에 대한 거리를 보여주는 화면은 아닙니다.

계산 방법 근거: pymoo NSGA-III 생존선택과 H=12·92개체 예제, 참조방향 생성 방법. 본 프로그램의 지도·비용·교차·변이는 이 합성 실험을 위해 별도로 명시한 가정입니다.

연결 및 실행 기록 복구

프로그램 폴더의 START_LIVE_UI.cmd를 두 번 클릭하면 로컬 서버를 시작하고 화면을 엽니다. 이미 켜져 있으면 이 폴더의 시작 기록과 계산 코드가 일치하는 서버만 다시 사용합니다. 코드가 다르거나 시작 기록을 확인할 수 없거나 점검 중이면 원인과 다음 행동을 알려 주며, 기존 계산을 자동 종료하거나 서버를 중복 실행하지 않습니다. 저장이 끝난 실행은 서버 재시작 후에도 ‘저장된 실행’에서 선택할 수 있습니다. 실행 도중 서버 자체가 종료되면 그 계산을 이어서 수행하는 기능은 없으며, 저장되지 않은 진행 결과는 복구 완료로 표시하지 않습니다. 연결이 끊겼다면 서버를 켠 뒤 ‘다시 연결’을 누르세요.

‘계산값 검산 완료’는 목적값을 다시 계산해 일치시켰다는 뜻이며 파일 저장 완료와 다릅니다. ‘저장 완료’가 확인된 실행만 결과를 다운로드할 수 있습니다. 실패 기록은 목록에서 원인을 확인할 수 있지만 불완전한 배치를 정상 결과로 열지는 않습니다. 다른 실행을 보던 중 실패 기록을 선택하면 기존 지도와 선택이 유지됩니다.

권한 오류는 결과 폴더의 쓰기 권한·파일 잠금을, 공간 부족은 디스크 여유 공간을 먼저 확인하세요. 문제를 해결한 뒤 새 계산을 시작합니다. 내부 진단은 해당 실행의 결과 폴더에 보존되며 화면의 실행 번호로 찾을 수 있습니다. 실패 기록과 기존 결과를 임의로 삭제하지 마세요. 결과 파일의 해시가 맞지 않는 실행은 사용하지 말고 관리자에게 점검을 요청하세요.
